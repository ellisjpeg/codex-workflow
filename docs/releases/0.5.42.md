# Workflow Alpha 1

Version: `0.5.42`. This is a regular Latest release. Alpha describes the
unfinished product scope; the included features must meet their release checks.
Workflow is an independent community project, not affiliated with or endorsed
by OpenAI. It modifies the local app bundle and ad-hoc re-signs it; keep the
verified backup and be prepared to use the guarded removal commands.

## Scope and compatibility

The alpha carries the audited Sidebar & navigation, Composer, Conversation
and Usage & indicators feature set. Release preparation adds third-party notices,
locally obtained native glyphs, a complete Workflow-authored cold preview and a
review-before-publication workflow. It does not add a separate update channel or change model selection, reasoning,
permissions or request contents.

Use macOS with Codex Desktop **26.908.40834, build 8881**, and Node.js 24.15.0
or newer in the 24.x line, or Node.js 26 or newer. The recorded native test
environment is Apple Silicon. Intel-native acceptance is not established.
An unsupported Codex build must be re-audited, not forced with `--allow-version`.

## Install or manually upgrade

These commands require the published alpha tag. Use a fresh source checkout:

```sh
git clone --branch v0.5.42 --single-branch https://github.com/ellisjpeg/codex-workflow.git codex-workflow-alpha-1
cd codex-workflow-alpha-1
npm ci --engine-strict
npm run setup -- --no-auto-repair
```

Review the isolated staging window when setup opens it. Save your work before
allowing installation and quitting Codex. A reapply uses the guarded existing-
installation path. Keep this checkout for status, recovery and removal.
The `codex-workflow-0.5.42.tar.gz` asset is the reduced updater payload,
not the source/test checkout needed by `npm run setup`.

## Update policy and limitations

Compatible existing installations can receive Alpha 1 through Update Workflow
using GitHub's `/releases/latest` feed. Manual upgrades use the exact tagged
source and guarded setup command above. A new Codex build still requires an
exact-build compatibility review; a release watcher cannot approve it alone.
Automatic post-Codex-update repair is explicitly disabled
when the documented setup command installs; an already-current no-op setup
does not change existing preferences.

Native selectors, layout tokens and installation checks are build-specific.
The native acceptance covers sampled states, not every locale, machine or
future Codex build. It is not a claim of a publicly distributed update
roundtrip. Keep private messages, tokens, account state and complete logs out
of bug reports. Use the repository's private security-reporting route for
security findings and its issue form for reproducible non-security bugs.

## Status, recovery and removal

From the retained checkout, inspect status first:

```sh
npm run status --silent
```

Quit Codex before removal. To restore the verified app backup:

```sh
npm run uninstall:patch
```

If status instead identifies a recoverable interrupted transaction, quit Codex
and run `npm run recover:patch` before further installation/removal. Stop for
inspection on unsafe journals, missing backups or unsupported versions. Do not
delete backups or suppress a failed guard. See `README.md`, `SECURITY.md` and
`THIRD_PARTY_NOTICES.md` in the source checkout.
